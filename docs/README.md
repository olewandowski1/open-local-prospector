# Documentation

Open Prospector keeps one living document for each kind of project truth.

| Document | Purpose |
|---|---|
| [Product Requirements](Product.md) | Product boundary, user journeys, acceptance criteria, and risks |
| [Domain Language](Domain-Language.md) | Canonical names used in code, storage, and the interface |
| [Architecture](Architecture.md) | Current system shape, boundaries, and trust model |
| [Architecture Decision Records](adr/) | Historical decisions and the reasoning behind them |
| [Contributing](../CONTRIBUTING.md) | Setup, verification, and contribution workflow |
| [Agent Instructions](../AGENTS.md) | Repository-specific engineering and design rules |

## Documentation Rules

- Use Title Case for document headings.
- Keep prose concise and use the terms defined in Domain Language.
- Describe the product as it works now; use decision records for historical reasoning.
- Use synthetic fixture data in screenshots, examples, and tests.
- Update links and product images whenever a documented workflow changes.
