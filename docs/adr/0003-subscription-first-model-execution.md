# Prefer subscription runtimes with an API fallback

The local first version will prefer installed, subscription-authenticated command-line agent runtimes so Oliver can use existing Codex, Claude Pro, and potentially OpenCode Go entitlements. Oliver installs and signs in through each provider's own terminal workflow before using it. Adapters will be implemented in the order Codex, Claude Code, then OpenCode and will invoke each client's supported non-interactive mode as a local subprocess. The application provides no provider login UI, stores no provider credentials, and never reads, extracts, copies, or reuses authentication tokens. Its runtime selector only reports executable readiness and the status exposed by the official client while remembering the last selection.

Each Prospecting Run uses one selected runtime. The application launches executables directly without a shell, uses fixed application-owned arguments, sends bounded stage inputs over standard input, and accepts only validated structured results over standard output. Source Content is never interpolated into a command, executable path, environment variable, or launch argument. The core does not depend on a shared provider SDK. An interrupted run may be resumed with another runtime, but the change is recorded. A Vercel AI SDK model gateway with OpenRouter remains an optional API-backed fallback for workloads that subscription runtimes cannot handle reliably; the run pauses and requires Oliver's explicit approval before using it, preventing silent provider changes or unexpected spending.
