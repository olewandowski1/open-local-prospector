# Prefer subscription runtimes with no usage-based fallback

The local first version will prefer installed, subscription-authenticated command-line agent runtimes so Oliver can use existing Codex and Claude Pro entitlements. Oliver installs and signs in through each provider's own terminal workflow before using it. Adapters will be implemented in the order Codex, then Claude Code, and will invoke each client's supported non-interactive mode as a local subprocess. The application provides no provider login UI, stores no provider credentials, and never reads, extracts, copies, or reuses authentication tokens. Its runtime selector only reports executable readiness and the status exposed by the official client while remembering the last selection.

Each Prospecting Run uses one selected runtime. The application launches executables directly without a shell, uses fixed application-owned arguments, sends bounded stage inputs over standard input, and accepts only validated structured results over standard output. Source Content is never interpolated into a command, executable path, environment variable, or launch argument. The core does not depend on a shared provider SDK. An interrupted run may be resumed with another runtime, but the change is recorded. There is no usage-based API fallback: a workload a subscription runtime cannot handle reliably pauses the run with completed work preserved, rather than switching to a metered provider behind Oliver's back. An API-backed gateway was considered and rejected (see the MVP quality gate).
