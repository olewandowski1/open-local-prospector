# Open Prospector Improvement Plans

Generated by the `improve` skill on 2026-08-23 from commit `b060b46`. This directory preserves the
full project audit and turns the recommended first tranche into executor-ready handoff plans. Read
this index before opening an individual plan.

## Current State

Open Prospector is a coherent pre-1.0 local product rather than a scaffold. The complete workflow
exists: local readiness, bounded discovery, identity evaluation, controlled website inspection,
runtime assessment, deterministic scoring, durable execution, review, correction, suppression,
export, deletion, backup, restore, and maintenance.

The repository contains 246 production TypeScript/TSX files (about 21,330 lines), 58 colocated unit
test files (about 5,093 lines), and 19 E2E/support files. The architecture is feature-owned, the web
and worker processes are separate, SQLite is the durable source of truth, and provider clients keep
their own credentials.

Verification performed during the audit:

| Command | Result |
|---|---|
| `pnpm check` | Passed: Biome, architecture, TypeScript, 350 unit tests, production build |
| `pnpm worker:check` | Passed |
| `pnpm test:e2e` | 77 passed, 33 intentionally skipped by project configuration |
| `pnpm test:e2e:workspace` | Passed |
| `pnpm audit --audit-level high` | No high or critical vulnerabilities |

The strongest parts of the project are its explicit product boundary, ADRs, durable task model,
source-content containment, bounded runtime processes, browser network policy, isolated destructive
tests, and careful presentation rules. Its largest maturity gap is outcome quality: the repository
proves the mechanics far better than it proves that real businesses, identities, citations, and
Website Opportunities are consistently correct.

## Recommended Later Sequence

1. **Trust and durability**: execute Plans 001-004, then address atomic workspace leases and process
   tree termination.
2. **Measurable candidate quality**: execute Plans 005-006, then strengthen opt-in live quality tests
   and review/export mutation coverage.
3. **Identity and accumulated workspace behavior**: fix same-name canonical collisions, move the
   review queue to server pagination, batch export queries, and add the missing indexes.
4. **Engineering enforcement**: run E2E in CI, add targeted Windows coverage, strengthen client
   boundary analysis, consolidate subprocess code, and finish documentation quick wins.
5. **Refactoring**: split the New Run workflow only after the quality and assembled-pipeline tests
   provide a stable safety net.

## Product Directions

### Local Quality And Calibration Laboratory

Turn persisted reports and Review Examples into a local-only evaluation view. Show explicitly
bounded counts, Shortlist Yield, rejection reasons, identity corrections, runtime, prompt/schema
version, and rubric version. Keep the analysis descriptive and manual, never an automatic prompt or
weight feedback loop.

### Replayable Prompt And Verifier Comparisons

Allow a maintainer to replay saved, redacted evidence through proposed prompt, schema, verifier, and
scoring versions. Diff attribution, rejected claims, Website Opportunity classes, and qualification
outcomes before spending subscription runtime calls on a live comparison.

### Additional Discovery Adapters Only After Measured Misses

Benchmark categories, places, and runtimes first. Add a bounded public adapter only when it closes a
documented coverage gap. Do not restore the superseded generic search-API design or scrape consumer
search-result interfaces.

### Desktop Packaging Only After Quality Stabilizes

A launcher and managed worker lifecycle may improve onboarding, especially on Windows, but native
SQLite, Chromium, provider discovery, signing, updates, and process management create a second
product surface. Revisit only after repeated setup evidence shows this is more valuable than
candidate-quality work.

## Findings Considered And Rejected

- **Move to PostgreSQL or add multiple workers**: rejected. The single-user SQLite/WAL/one-worker
  design is deliberate and proportionate under ADRs 0001 and 0007.
- **Restore per-business corroboration search**: rejected. ADR 0013 records both the attribution
  failures and the roughly 200 extra searches it caused for 97 businesses.
- **Adopt Effect in React or as durable workflow state**: rejected. ADR 0010 keeps Effect in scoped
  worker/server execution and SQLite as durable authority.
- **Schedule a framework or dependency migration**: rejected. Core packages are on current major
  lines, and the only audit advisory is a moderate development-only esbuild path whose server is not
  used here.
- **Add outreach, CRM, recurring monitoring, cloud accounts, telemetry, or automatic learning**:
  rejected. These contradict the product's explicit non-goals and would require a privacy,
  persistence, and authority redesign.
- **Treat the two Playwright packages as duplication**: rejected. `playwright` is an application
  runtime dependency for website inspection; `@playwright/test` drives repository tests.

## Audit Limits

The audit did not execute real subscription-runtime runs, inspect arbitrary real external websites,
benchmark a workspace containing thousands of candidates, or test macOS/Linux hosts. Those require
provider usage, external-state variability, or purpose-built benchmark environments. The source
audit and local verification were performed on Windows against the isolated synthetic workspaces.
